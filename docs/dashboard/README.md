# CWIZ Enterprise 운영현황 대시보드 인수인계 가이드

> 다른 담당자 또는 AI가 기존 정책과 기능을 유지하면서 대시보드를 수정할 수 있도록 만든 기준 문서입니다.

- 최종 갱신일: 2026-08-27
- 운영 파일: `docs/dashboard/index.html`
- 공개 주소: <https://hikary83.github.io/kic-worktools/dashboard/>
- 관련 Jira: `CW2R-73` — `[CWIZ Enterprise] Admin 대시보드 및 통계 기능 단계별 구축`
- 고객 활동 기능 반영 커밋: `e41e1be`

## 1. 목적과 범위

CWIZ Enterprise Admin에 정식 대시보드·통계 기능이 개발되기 전까지 사용하는 임시 운영 보고 화면이다. 매주 CWIZ Enterprise에서 내려받은 Excel 파일을 사용해 다음 흐름을 한 화면에서 확인한다.

`이용신청 → 승인 → 고객사 등록 → 계측기 등록 → CMS 매핑 → 고객 사용 활동`

현재 범위에는 견적, 교정의뢰, 접수, 진행, 완료, 매출 통계를 포함하지 않는다. 원본 Excel에 없는 데이터는 추정하거나 만들어내지 않는다.

## 2. 운영 및 기술 원칙

1. 대시보드 수치는 업로드한 Excel 데이터에서만 계산하며 숫자를 하드코딩하지 않는다.
2. 원본 Excel은 읽기만 하며 수정하지 않는다.
3. 파일은 브라우저 메모리에서 처리한다. 별도 서버나 API로 Excel 내용을 전송하지 않는다.
4. 새로고침하면 선택한 파일과 계산 결과는 초기화된다. 브라우저 저장소에 데이터를 보관하지 않는다.
5. 외부 JavaScript 라이브러리나 CDN 없이 단일 HTML 파일로 동작한다.
6. 최신 Chrome 또는 Edge 사용을 기준으로 한다.
7. 현재 지원 확장자는 `.xlsx`뿐이다. `.xls`와 `.xlsm`은 지원하지 않는다.
8. UI는 PC 보고용이며 1440px 이상에서 보기 좋도록 구성한다.
9. 기존 기능을 수정할 때 다른 KPI·차트·표의 집계 정책을 임의로 바꾸지 않는다.

`index.html` 한 파일 안에 모든 기능이 들어 있다.

- 상단 `<style>`: 브랜드 컬러, 레이아웃, KPI·차트·표 스타일
- 본문 `<body>`: 파일 선택, KPI, 차트, 고객 활동, 표
- 하단 `<script>`: Excel 압축 해제·파싱, 검증, 집계, 렌더링, 이벤트 처리

## 4. 매주 사용하는 입력 파일

동일 기준일의 다음 4개 파일이 모두 필요하다.

| 역할 | 파일명 예시 | 화면 역할 |
|---|---|---|
| 이용신청 | `이용신청_2026-08-27.xlsx` | 신청·승인·대기·반려 및 신청 업체 내역 |
| 고객사현황 | `고객사현황_2026-08-27.xlsx` | 등록 고객사, 상태, 담당자 |
| 고객사계측기현황 | `고객사계측기현황_2026-08-27.xlsx` | 자산, CMS 매핑, 차기교정 현황 |
| 데이터변경이력 | `데이터변경이력_2026-08-27.xlsx` | 고객사의 실제 CWIZ 데이터 작업 로그 |

파일명에서 `YYYY-MM-DD` 형태의 날짜를 찾아 기준일로 사용한다. 네 파일의 기준일이 다르면 적용하지 않고 오류를 표시한다.

### 필수 컬럼

| 파일 | 필수 컬럼 |
|---|---|
| 이용신청 | 신청일자, 상태, 회사명, 사업자등록번호, 승인일자, 회사코드 |
| 고객사현황 | 회사코드, 회사명, 사업자번호, 보유자산, 상태, 영업 담당자, 등록일 |
| 고객사계측기현황 | 회사명, 사업자번호, 총자산, 미매핑, 교정 준비, 교정 임박, 기한 초과, 상태 |
| 데이터변경이력 | 일시, 고객사, 사용자, 아이디, 메뉴, 로그 유형, 대상, 변경 항목, 변경 전, 변경 후 |

다음 컬럼명은 같은 의미로 허용한다.

- `사업자번호` ↔ `사업자등록번호`
- `영업 담당자` ↔ `영업담당자`
- `교정 준비` ↔ `교정준비`
- `교정 임박` ↔ `교정임박`
- `기한 초과` ↔ `기한초과`
- `로그 유형` ↔ `로그유형`
- `변경 항목` ↔ `변경항목`
- `변경 전` ↔ `변경전`
- `변경 후` ↔ `변경후`

컬럼을 찾을 때 제목의 공백, `*`, BOM 문자는 무시한다. 원본 데이터 값 자체는 변경하지 않는다. 시트별 상단 10개 행 안에서 필수 컬럼이 가장 많이 일치하는 행을 헤더로 선택한다.

## 5. 핵심 집계 정책

### 이용신청과 승인

- 이용신청: 이용신청 파일의 데이터 행 전체 수
- 승인·대기·반려: `상태` 값이 각각 정확히 일치하는 행 수
- 승인 고객사 KPI: 승인 행의 고유 사업자등록번호 수
- 사업자등록번호가 비어 있으면 회사명을 중복 판정의 대체 키로 사용
- 이용신청 카드의 승인 수는 승인 신청 건수이며, 승인 고객사 카드는 고유 고객사 수이므로 데이터에 따라 서로 다를 수 있음

### 등록 고객사

- 등록 고객사: 고객사현황 파일의 데이터 행 전체 수
- 정상·비활성: `상태` 값이 각각 정확히 일치하는 행 수

### 계측기와 CMS 매핑

- 등록 계측기: 고객사계측기현황의 `총자산` 합계
- 미매핑 계측기: `미매핑` 합계
- 매핑 완료: `총자산 - 미매핑`
- 매핑률: `(총자산 - 미매핑) ÷ 총자산 × 100`
- 총자산이 0이면 매핑률 계산 오류가 발생하지 않도록 0으로 처리
- 고객사 운영현황은 기본적으로 총자산 내림차순 TOP 10
- 미매핑, 교정 임박, 기한 초과 기준으로 정렬을 바꿀 수 있음

### 차기교정 관리

- 교정 준비·교정 임박·기한 초과는 원본 파일의 같은 이름 컬럼을 각각 합산
- 대시보드에서 날짜를 다시 계산하거나 상태를 재분류하지 않음

### 담당자 운영현황

- 고객사현황의 `영업 담당자`를 기준으로 집계
- 고객사현황과 고객사계측기현황은 숫자 이외 문자를 제거한 사업자등록번호로 연결
- 사업자등록번호가 일치하지 않으면 해당 고객사의 계측기 수치는 담당자 합계에 포함되지 않음
- 원본에 담당지사 컬럼이 없으므로 지사 집계는 하지 않음

## 6. 기간 정책

`이번 주`는 파일명 기준일이 속한 주의 월요일부터 기준일까지다.

예: 기준일이 `2026-08-27`이면 이번 주는 `2026-08-24~2026-08-27`이다.

### 이용신청 처리 현황

- 이번 주: 신청일자가 월요일~기준일에 포함된 신청만 집계
- 이월 대기: 이번 주 월요일보다 이전에 신청됐고 현재 상태가 `대기`인 건
- 전체 미처리: 이용신청 파일 전체에서 현재 상태가 `대기`인 건
- 파일 전체: 업로드한 이용신청 파일의 모든 행을 집계

### 고객 사용 활동

- 이번 주: 로그 `일시`의 날짜가 월요일~기준일에 포함된 행
- 파일 전체: 업로드한 데이터변경이력 파일의 모든 행
- 활동 고객사: 선택 기간의 고유 고객사 수
- 활동 사용자: `고객사 + 아이디` 조합의 고유 수. 아이디가 없으면 사용자명을 사용
- 작업 로그: 선택 기간의 로그 행 전체 수
- 활동 고객사 TOP 5: 작업 로그 수 내림차순, 동률이면 최근 활동 순
- 최근 활동: 선택 기간의 일시 내림차순 최근 8건

현재 버전은 현재 상태를 보여주는 Snapshot 중심이다. 전주 대비 증감은 이전 주 파일을 함께 입력받는 기능이 추가되기 전까지 계산하지 않는다.

## 7. 고객 활동 로그 분류 정책

분류는 아래 우선순서로 적용한다.

1. `변경 항목`이 `첨부 추가`이면 **첨부 추가**
2. `메뉴=사용자 관리`이고 `로그 유형=등록`이면 **사용자 등록**
3. `메뉴=계측기 통합 대장`, `로그 유형=등록`, `변경 후=계측기 등록`이면 **계측기 등록**
4. `로그 유형=수정`이면 **정보 수정**
5. 위 조건에 해당하지 않으면 원본의 로그 유형을 사용하고, 로그 유형도 없으면 **기타**

작업 유형 막대는 현재 네 유형(계측기 등록, 정보 수정, 첨부 추가, 사용자 등록)을 표시한다. 새로운 유형은 작업 로그 전체 수와 최근 활동 표에는 포함되지만, 막대에 표시하려면 `renderActivitySection()`의 유형 목록과 HTML 막대를 함께 추가해야 한다.

보고 모드는 파일 업로드 영역과 성공 안내 등을 숨겨 캡처·인쇄에 적합한 화면으로 바꾼다.

## 9. 오류 및 데이터 보호 정책

다음 경우 화면을 갱신하지 않고 사용자가 이해하기 쉬운 오류를 표시한다.

- 4개 파일 중 하나라도 선택하지 않음
- 확장자가 `.xlsx`가 아님
- 파일명에서 기준일을 찾지 못함
- 네 파일의 기준일이 서로 다름
- 필수 컬럼이 누락됨
- 데이터 행이 없음
- Excel ZIP/XML 구조가 손상됨
- 브라우저가 필요한 압축 해제 기능을 지원하지 않음

원본 문자열을 HTML에 표시할 때는 `escapeHtml()`을 거쳐 태그나 스크립트로 해석되지 않도록 한다.

## 11. 수정 시 주요 코드 위치

`index.html`에서 함수명으로 검색하는 것이 가장 빠르다.

| 목적 | 코드/함수 |
|---|---|
| 파일별 필수 컬럼 | `const schemas` |
| 파일명 기준일 | `extractDate()` |
| Excel 읽기 | `unzip()`, `parseXlsx()` |
| 헤더·필수 컬럼 검증 | `datasetFromSheets()` |
| 고객 활동 유형 | `classifyActivityRecord()` |
| 전체 KPI·행 데이터 | `compute()` |
| 이번 주 시작일 | `weekStartIso()` |
| 신청 차트 | `renderApplicationChart()` |
| 고객 활동 | `renderActivitySection()` |
| 전체 화면 반영 | `render()` |

입력 파일을 새로 추가할 때는 파일 선택 HTML, `schemas`, `selectedFiles`, 적용 버튼의 파싱 순서, `compute()`, 화면 렌더링을 함께 수정해야 한다.

## 12. 수정·검증 체크리스트

1. 작업 전 Git 상태를 확인하고 사용자나 다른 작업의 변경사항을 덮어쓰지 않는다.
2. 기존 네 파일 업로드와 모든 KPI·차트·표를 유지한다.
3. 숫자를 직접 입력하지 않고 `compute()` 결과를 사용한다.
4. 동일 기준일 검증과 필수 컬럼 오류 안내를 유지한다.
5. 2026-08-27 기준 파일로 위 회귀 기준값을 확인한다.
6. `이번 주 / 파일 전체` 전환을 각각 확인한다.
7. 고객명·사용자명·대상·변경내용이 긴 경우 레이아웃이 깨지지 않는지 확인한다.
8. 보고 모드와 인쇄 화면을 확인한다.
9. `git diff --check`로 공백 오류를 확인한다.
10. 변경한 파일만 커밋하고 공개 페이지가 갱신됐는지 확인한다.

## 13. 배포 방법

GitHub Pages는 이 저장소의 `docs` 폴더를 사용한다. `main` 브랜치에 푸시하면 잠시 후 공개 주소에 반영된다.

```powershell
git -C "D:\Google Antigravity\kic-worktools" status --short
git -C "D:\Google Antigravity\kic-worktools" diff --check
git -C "D:\Google Antigravity\kic-worktools" add docs/dashboard/index.html docs/dashboard/README.md
git -C "D:\Google Antigravity\kic-worktools" commit -m "docs: update dashboard guide"
git -C "D:\Google Antigravity\kic-worktools" push origin main
```

배포 후 <https://hikary83.github.io/kic-worktools/dashboard/>를 새로 열어 확인한다. 이전 화면이 캐시되어 보이면 강력 새로고침을 사용한다.

## 15. 다른 AI가 작업을 이어갈 때

새 작업을 시작하기 전에 이 문서와 `index.html`을 함께 읽고, 실제 Excel 컬럼과 현재 코드를 확인한다. 사용자의 명시적인 요청이 없는 한 기존 집계 정책을 바꾸거나 원본에 없는 값을 추정하지 않는다. 변경 후에는 최소한 네 파일 파싱, 핵심 기준값, 기간 전환, 공개 페이지 반영 여부까지 검증한다.
